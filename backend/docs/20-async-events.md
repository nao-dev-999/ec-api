# 20. 非同期処理・イベント駆動の方式

> [← インデックスに戻る](../コーディング規約.md)

---

[11. 非同期処理と仮想スレッド](11-async-virtual-threads.md)は「仮想スレッド環境で何が禁止か」という実装制約を扱うが、本章は「そもそも処理を同期でやるか非同期でやるかをどう判断するか」という設計方針を扱う。

## 同期 / 非同期の判断基準

| 状況 | 方式 | 例 |
|---|---|---|
| 処理結果をレスポンスに含める必要がある | 同期 | 注文作成時の在庫減算・金額計算 |
| 処理結果をクライアントが待つ必要がない、かつ失敗してもユーザー操作自体は成功扱いでよい | 非同期 | 注文確定後の確認メール送信、管理者への通知 |
| 重い集計・外部API呼び出しが絡み、APIのレスポンスタイムに影響させたくない | 非同期 or batch | 売上集計、レコメンド更新 |
| 定期実行でよい（リアルタイム性が不要） | batchモジュールに置く | 日次の在庫レポート、決済消込（`PaymentReconciliation`） |

**判断に迷った場合は同期から始める**。非同期化は後からでも追加できるが、「本来同期であるべき処理を非同期にしてしまい、失敗が検知されない」方が事故につながりやすい。

## APIとbatchの責務分界

本プロジェクトは `backend`（API）と `batch`（定期実行ジョブ）が別モジュールとして存在する。責務の置き場所を以下で統一する。

```
// ✅ APIがキックすべきもの: ユーザー操作に起因し、即時性が必要
POST /api/orders → 注文作成 → 在庫減算（同期・トランザクション内）

// ✅ batchに置くべきもの: 時間起点で実行され、個別ユーザー操作に紐付かない
日次バッチ: 当日の注文を集計して売上レポートを生成する
日次バッチ: 決済代行の明細とDBの注文を突合する（PaymentReconciliation）

// ❌ 避ける: ユーザー操作直後に必要な処理をbatchの次回実行まで待たせる
注文確定 → （次の日次バッチまで）在庫を減算しない
```

APIからbatchの処理を直接トリガーする必要が生じた場合（「今すぐ集計し直したい」等の管理者操作）は、batch側にAPI経由で起動できるエンドポイント/キューを用意するのではなく、まず「本当に即時実行が必要か」を見直す。必要であれば管理者向けのアクションエンドポイント（`POST /api/admin/reports/trigger` 等）として明示的に設計し、内部でbatchと同じService/ロジックを呼び出す。

## 非同期処理の実装方式

アプリ内非同期（`@Async`）とメッセージキュー（SQS等）のどちらを使うかは処理の性質で決める。

| 方式 | 採用基準 |
|---|---|
| `@Async`（仮想スレッド上で実行） | 失敗してもリトライ不要・ログに残れば十分な処理（通知メール送信等）。プロセスが落ちると処理も失われる点に注意 |
| メッセージキュー（SQS等） | 失敗時に確実にリトライしたい処理、他サービス（batch等）と処理を共有したい場合、処理量がスパイクしてもAPIのレスポンスタイムに影響させたくない場合 |

```java
// ✅ @Asyncを使う場合: 失敗が許容できる通知処理に限定する
@Async
public void sendOrderConfirmationEmail(Long orderId) {
    // 失敗してもログに記録されれば良い。再送が必要な処理には使わない
}

// ❌ @Asyncで在庫減算のような失敗が許されない処理を行わない
// (例外がCallerに伝わらず、サイレントに失敗する)
@Async
public void decrementStock(Long productId, int quantity) { ... }
```

`@Async` を使う場合、例外は呼び出し元に伝播しないため、`AsyncUncaughtExceptionHandler` を必ず設定し、失敗がログから追跡できるようにする。

## チェックリスト

- [ ] 処理結果をレスポンスに含める必要がある処理を非同期化していない
- [ ] 失敗時にリトライが必要な処理に `@Async` を使っていない（キュー方式を検討している)
- [ ] `@Async` メソッドの例外を `AsyncUncaughtExceptionHandler` で捕捉している
- [ ] ユーザー操作起点の処理をbatchの定期実行任せにしていない
